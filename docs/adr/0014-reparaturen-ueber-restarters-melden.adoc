= 0014 Reparaturen über Restarters.net an die Open Repair Alliance melden

[horizontal]
Status:: angenommen
Datum:: 2026-11-08
Beteiligte:: Michael Prange
Überarbeitet:: 2026-11-09, Klarstellung bei der Durchsicht

== Kontext und Problem

Die Reparaturdaten des Repair Café sollen bei der Open Repair Alliance landen. Bisher geschah das über Laufzettel auf reparatur-initiativen.org. Die API der anstiftung kann aber nur lesen, Laufzettel gibt es nur als Webformular. MANUEL soll die Daten ohne Abtippen übertragen.

== Entscheidungskriterien

* Daten landen bei der Open Repair Alliance
* Übertragung über eine API
* Keine doppelte Zählung

== Betrachtete Optionen

* Restarters.net mit API
* Laufzettel bei der anstiftung, MANUEL füllt nur vor
* Formular der anstiftung automatisch ausfüllen
* Schreibende API bei der anstiftung anregen

== Entscheidung

Reparaturen meldet MANUEL über die API von Restarters.net. Ein Gerät wird mit `POST /api/v2/devices` beim passenden Event angelegt. Bei der anstiftung führt das Repair Café weiter die Termine, damit Gäste sie abonnieren können, und die Neuigkeiten. Laufzettel entfallen, denn die Open Repair Alliance bittet, nur ein Werkzeug zu nutzen.

Die Kategorie für Restarters folgt aus der ORA-Gruppe im Katalog. Als `item_type` sendet MANUEL den englischen Namen, aus dem die Alliance feinere Gruppen ableitet. Am 09.11.2026 fehlt er noch bei 863 von 1.089 Einträgen des Katalogs. Wir erarbeiten ihn noch, bis dahin bleiben diese Geräte offen.

Je Termin legt n8n mit `POST /api/v2/events` ein Event an. Je nach Netzwerk muss es erst freigegeben werden. Dafür braucht das Repair Café eine eigene Gruppe bei Restarters. Von den sechs Hindernissen des Standards nimmt die API nur fünf an, „Item too worn out“ fehlt.

Offen ist, ob der Defekt bei der laufenden Meldung mitgeht. Nach xref:0036-reparaturen-ab-2024-an-restarters-nachmelden.adoc[ADR 36] geht er erst nach der Anonymisierung mit, und neue Tickets ab 2027 werden nach xref:0039-nur-tickets-von-2025-und-2026-anonymisieren.adoc[ADR 39] nicht anonymisiert. Ohne eigene Regel bliebe der Defekt also leer.

=== Konsequenzen

* Gut, weil keine Daten mehr abgetippt werden.
* Schlecht, weil Termine an zwei Stellen gepflegt werden.
* Schlecht, weil Restarters bei Laptops und Fernsehern die Größe verlangt. MANUEL muss danach fragen.
* Schlecht, weil der API-Token bisher nur über das Cookie der Anmeldung zugänglich ist.

== Vor- und Nachteile der Optionen

=== Restarters.net mit API

* Gut, weil eine offene API Geräte anlegen kann und die Daten von dort zur Alliance gehen.
* Schlecht, weil Termine zusätzlich als Events bei Restarters stehen.

=== Laufzettel, MANUEL füllt vor

* Gut, weil alles bei der anstiftung bliebe.
* Schlecht, weil jemand jeden Laufzettel weiter von Hand absenden müsste. Genau daran ist die Meldung bisher gescheitert.

=== Formular automatisch ausfüllen

* Gut, weil es ohne neue Plattform ginge.
* Schlecht, weil jede Änderung am Formular den Ablauf bricht und es ohne Absprache mit der anstiftung nicht in Frage kommt.

=== Schreibende API bei der anstiftung

* Gut, weil alles bei einer Plattform bliebe.
* Schlecht, weil sie erst entwickelt werden müsste.
