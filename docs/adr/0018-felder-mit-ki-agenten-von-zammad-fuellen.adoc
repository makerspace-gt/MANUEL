== Kontext und Problem

MANUEL soll im Ticket Felder füllen und interne Notizen schreiben. Das kann Zammad selbst über seine KI-Agenten, oder ein externer Workflow in n8n ruft das Modell auf und schreibt über die API zurück.

== Entscheidungskriterien

* Wenig eigener Code
* Ergebnisse direkt im Ticket
* Auslösen über die gewohnten Trigger von Zammad

== Betrachtete Optionen

* KI-Agenten und KI-Funktionen von Zammad mit dem Mini-PC als Anbieter
* n8n-Workflows auch für die Felder

== Entscheidung

Zammad füllt die Felder selbst über seine KI-Agenten. Dazu gehören Ticket Categorizer für Auswahlfelder auch als Baum, Ticket Text Extractor für Text und Custom AI Agent für Notizen. Ein Agent wird über einen normalen Trigger ausgelöst und wendet sein Ergebnis mit denselben Aktionen an. n8n übernimmt nur Aufgaben außerhalb von Zammad.

Zammad bietet außerdem Title Rewriter, Tagger, Prioritizer und Group Dispatcher. Der Title Rewriter könnte Tickets ohne Betreff einen Titel geben, ein Problem aus xref:0006-gegenstaende-erst-herausziehen.adoc[ADR 6]. Jede Änderung durch einen Agenten steht mit seinem Namen im Verlauf des Tickets.

=== Konsequenzen

* Gut, weil Zammad die Ergebnisse ohne eigene Schnittstelle ins Ticket schreibt.
* Schlecht, weil Zammad laut Quellcode keine Kontextlänge mitschickt. Die muss der Server auf dem Mini-PC vorgeben.
* Schlecht, weil der Ticket Categorizer keine Sicherheit zurückgibt. Die Einordnung aus xref:0010-mit-vertreter-namen-einordnen.adoc[ADR 10] und xref:0011-bei-unsicherheit-nachfragen.adoc[ADR 11] braucht dafür einen eigenen Workflow. Wie wir trotzdem mit den Agenten beginnen, regelt xref:0040-mit-dem-ticket-categorizer-von-zammad-beginnen.adoc[ADR 40].

== Vor- und Nachteile der Optionen

=== KI-Agenten von Zammad

* Gut, weil Ergebnisse ohne eigenen Code und mit Eintrag im Verlauf ins Ticket kommen.
* Schlecht, weil wir nur nutzen können, was die Agenten anbieten, etwa keine Sicherheit beim Categorizer.

=== n8n-Workflows auch für die Felder

* Gut, weil wir Modelle, Prompts und Regeln frei wählen.
* Schlecht, weil jeder Workflow eigene Schnittstellen zu Zammad und eigene Pflege braucht.
