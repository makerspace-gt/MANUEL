= 0071 Etherpad vorübergehend für Anmerkungen des Teams

[horizontal]
Status:: angenommen
Datum:: 2026-11-21
Beteiligte:: Michael Prange

== Kontext und Problem

Das Team soll Texte wie die Fallstudie oder einzelne ADRs einfach kommentieren können, ohne Konto bei GitHub oder claude.ai. Claude Code soll die Anmerkungen lesen und Texte zum Kommentieren hineinschreiben können. Die Nextcloud des Vereins zieht erst mit dem Neuaufbau der IT um. Die Kommentare zur Fallstudie mit Isso aus {repo}/docs/recherche/kommentarsystem.md[kommentarsystem.md] brauchen eine VM des Vereins.

== Entscheidungskriterien

* Ohne Konto nutzbar
* Lesen und Schreiben über eine Schnittstelle
* Keine Daten bei fremden Anbietern
* Schnell aufgebaut und wieder entfernt

== Betrachtete Optionen

* Etherpad auf MANUEL im Tailnet
* Nextcloud des Vereins mit der App Text
* Claude Docs
* Kommentare auf GitHub
* Öffentliche Pads wie CryptPad oder HedgeDoc

== Entscheidung

Ein Etherpad läuft vorübergehend auf MANUEL. Es ist ein einzelner Container mit `podman run`, nicht Teil des Images und nicht in `zammad/compose.yml`.

* Image `docker.io/etherpad/etherpad:3.3.15` mit fester Version. Neuere Versionen kamen fast täglich, gewählt ist die neueste, die mindestens zwei Wochen alt war.
* Der Container hört nur auf `127.0.0.1:9001`. `tailscale funnel` stellt ihn mit HTTPS unter `https://manuel.zebra-alewife.ts.net/` im Internet bereit, ohne Passwort. Das ist eine Ausnahme von xref:0047-dienste-zum-testen-im-tailnet-oeffnen.adoc[ADR 47], damit auch Engagierte ohne Zugang zum Tailnet mitschreiben können. Alle anderen Dienste auf MANUEL bleiben im Tailnet.
* `EDIT_ONLY=true`, so lassen sich vorhandene Pads bearbeiten, aber über die Oberfläche keine neuen anlegen.
* Daten in SQLite unter `/var/lib/manuel/etherpad`, kein Konto für Admins.
* Das Pad `fallstudie` enthält die ganze Fallstudie mit Anhang als lesbaren Text, gerendert mit demselben Image wie in der CI. Überschriften sind fett, Tabellen stehen Zeile für Zeile, Bilder als Beschreibung, umgewandelt mit {repo}/case-study/etherpad_html.py[etherpad_html.py]. Anmerkungen aus dem Pad prüft ein Mensch, bevor sie in die Fallstudie kommen.
* `AUTHENTICATION_METHOD=apikey` schaltet die alte Schnittstelle mit Schlüssel ein. Der Schlüssel liegt in `APIKEY.txt` im Container, wird nur auf MANUEL gelesen und nie ausgegeben. Er wechselt, wenn der Container neu entsteht.
* Jedes Pad beginnt mit dem Hinweis, keine Namen, Adressen oder anderen Angaben zu Gästen einzutragen.

Zum Entfernen:

----
sudo tailscale funnel --https=443 off
sudo podman rm -f etherpad
sudo rm -rf /var/lib/manuel/etherpad
----

=== Konsequenzen

* Gut, weil alle ohne Konto und ohne Tailnet mitschreiben können und die Texte auf MANUEL bleiben.
* Gut, weil Claude Code Texte über die Schnittstelle einstellen und Anmerkungen lesen kann.
* Schlecht, weil jeder mit der Adresse alles lesen und ändern kann, auch Bots. Die Fallstudie ist ohnehin öffentlich, Änderungen lassen sich über den Verlauf des Pads zurückholen.
* Schlecht, weil MANUEL mit den echten Tickets damit aus dem Internet erreichbar ist. Eine Lücke in Etherpad wäre ein Weg dorthin. Das Pad läuft deshalb nur so lange wie nötig.
* Schlecht, weil es keine Sicherung und keine Updates gibt. Das passt nur, solange es vorübergehend ist.
* Schlecht, weil Etherpad Namen nur freiwillig zeigt. Wer was schrieb, zeigen nur die Farben der Autoren.

== Vor- und Nachteile der Optionen

=== Nextcloud des Vereins

* Gut, weil Freigaben ohne Anmeldung möglich sind und die Dateien beim Verein bleiben
* Schlecht, weil die Nextcloud erst mit dem Neuaufbau der IT umzieht

=== Claude Docs

* Gut, weil Claude direkt schreiben kann
* Schlecht, weil alle Zugriff auf claude.ai brauchen und die Texte bei Anthropic liegen

=== Kommentare auf GitHub

* Gut, weil die Anmerkungen direkt an den Zeilen im Repo stehen
* Schlecht, weil alle ein Konto bei GitHub brauchen

=== Öffentliche Pads

* Schlecht, weil CryptPad keine Schnittstelle hat, HedgeDoc 1 vorhandene Notizen nicht über eine Schnittstelle ändern kann und öffentliche Etherpads keinen Schlüssel für die Schnittstelle herausgeben

== Quellen

* `settings.json` im Image 3.3.15, `authenticationMethod` steht dort standardmäßig auf `sso`
* Versionen und Datum der Tags von `etherpad/etherpad` auf Docker Hub, abgerufen am 21.11.2026
* Ausgabe von `tailscale serve status` auf MANUEL, „tailnet only“
