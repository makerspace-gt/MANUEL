= 0074 Zammad 7.3 vor dem Start

[horizontal]
Status:: angenommen
Datum:: 2026-11-28
Beteiligte:: Michael Prange

== Kontext und Problem

Zammad 7.3.0 erschien am 26.11.2026, das Image `7.3.0-0001` von zammad-docker-compose kurz danach. Das echte Zammad läuft mit 7.2, die Testinstanz mit 7.2.2. MANUEL hängt sich an mehreren Stellen in Zammad ein, als Initializer, über eigene Agenten und Trigger und über Skripte. Soll der Echtbetrieb am 05.12.2026 auf 7.2 oder 7.3 starten?

== Entscheidung

Der Echtbetrieb startet auf 7.3. Erst läuft die Generalprobe nach xref:0073-generalprobe-mit-dem-ganzen-backup.adoc[ADR 73] in der Testinstanz auf 7.3, dann wird das echte Zammad vor dem 05.12. aktualisiert. Die Regel, neue Versionen erst nach zwei Wochen zu nehmen, gilt hier ausnahmsweise nicht, damit der Echtbetrieb nicht kurz nach dem Start ein großes Update braucht. Vor dem Update im echten Zammad holen wir den neuesten Patch von 7.3.

`quellen/zammad` steht dafür auf dem Tag `7.3.0`, `quellen/zammad-docker-compose` auf dem Stand mit 7.3.0-0001 als Standard.

Gelesen wurden die Änderungen von 7.2.2 bis 7.3.0 an allen Stellen, an denen MANUEL andockt. Es sind 748 Commits.

Neu in 7.3 ist eine Übersetzung von Nachrichten über einen externen Dienst. Sie ist ab Werk aus und bleibt aus, weil Text dabei das Haus verlassen würde, siehe xref:0048-keine-personenbezogenen-daten-nach-aussen-geben.adoc[ADR 48].

=== Konsequenzen

* Gut, weil der Echtbetrieb auf der aktuellen Version beginnt und Anpassungen nur einmal geprüft werden müssen.
* Gut, weil die Links im Code auf die eingesetzte Version zeigen.
* Schlecht, weil 7.3.0 erst wenige Tage alt ist und noch kaum Patches hat.
* Schlecht, weil die Generalprobe zugleich Update und Einrichtung von MANUEL prüft. Läuft etwas schief, ist die Ursache schwerer zu finden.
